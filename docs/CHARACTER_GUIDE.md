# キャラクター追加ガイド

新しいキャラクターの姿勢・部品・描画順を設計するためのガイドです。剣士・弓使い (実験B〜E) とStudioでの追加制作で確かめたやり方をまとめています。
**共通の `src/` と依頼対象以外の完成済みキャラクターは原則変更しません。** 制作・登録・確認範囲の手順は [STUDIO_GUIDE.md](STUDIO_GUIDE.md) にまとめています。

**人間型の頭身は灰燼の衛士を基準に約2.2頭身**とします。寸法・計測方法・制作AIへの指示は [STUDIO_GUIDE.md の人間型の標準頭身](STUDIO_GUIDE.md#人間型の標準頭身灰燼の衛士を基準)を適用してください。

## 0. どのファイルに何を書くか

| 置き場所 | 内容 |
|---|---|
| `characters/<slug>/character.js` | 姿勢・部品の描き方・組み立て・定義。制作部品は `../../src/authoring.js` から import |
| 同じキャラクターフォルダの補助モジュール | 必要に応じて分割するキャラクター固有の処理。静的な相対importで参照 |
| `characters/catalog.generated.js` | `node tools/sync-catalog.mjs` で生成する登録情報。手編集しない |
| 既存Studioのギャラリー・詳細画面 | カタログから追加キャラクターを表示。UIや組み込み登録簿の編集は不要 |

追加キャラクターの見本は [魔法使い](../characters/mage/character.js)、[灰燼の衛士](../characters/warrior/character.js)、[王](../characters/king/character.js) です。共通リグを使った描画の参考として、`src/characters/` の剣士・弓使いも参照できます。

## 1. 定義の形

InkstoneのCharacterDefinitionを `character`、表示情報を `studio` としてnamed exportします。登録形式のテンプレートは [STUDIO_GUIDE.md の単一の追加方法](STUDIO_GUIDE.md#単一の追加方法)、APIの契約は [API_REFERENCE.md](API_REFERENCE.md) を参照してください。以下では姿勢・描画の実装に必要な点を説明します。

## 2. 共通リグの使い方

- **体の座標系**: `a` = 前、`b` = 左、`z` = 上 (ローカル px、足元が原点)。4方向の違いは「前ベクトル」だけなので、姿勢は1つ書けば4方向に使えます。
- `rigFrame(direction, body, yaw)` が座標の変換を返します。
  - `W(a, b, z)`: 体の座標 → 画面のローカル座標 (`d` = 奥行き)
  - `U(a, b, z)`: 上半身の揺れ `body = [da, db, dz]` を加えたもの
  - `UY(a, b, z)`: さらに上半身のひねり `yaw` を加えたもの (弓の構えで左肩を前へ出すのに使った)
  - `sx` (+1 / −1): 画面上で右を向いているか (横顔の部品を左右反転するときに使う)。`front`: 正面系 (↙↘) か背面系 (↖↗) か
- 脚は `legParts2(ctx, rf, P, { pants, boot, cuff, bootH, footR, soleR })` を使うと、太さのある脚とブーツ・**足の接地補正** (滑り防止) が付きます。歩行の足運びは `walkFeet(t)` (足の位置 `footL` / `footR` と上下の揺れ `bob`)。
- 腕は `ik2(肩, 手, 上腕の長さ, 前腕の長さ, 肘を曲げる方向)` で肘の位置を求めます。IKが成立していても、自然な構えになるとは限りません。肩と手の距離が腕の全長に対して短すぎると肘が深く曲がるため、手の位置・腕の長さ・肘の曲がる方向を合わせて調整します。
- 描画は `renderRig(ctx, x, y, scale, parts, { prefix: 'mage', boil, shadow: opts.shadow })`。部品ごとに乱数を固定するので、同じ時刻なら毎回同じ絵になります。`boil = DRAW.boil ? Math.floor(t * 5) % 3 : 0` (線のゆらぎ)。

## 3. 4方向のポーズとアニメーション

- 姿勢関数 `pose(action, t)` は **体の座標系** の値だけを返します (手の位置・武器の向き・足・上半身の揺れ)。画面の向きは考えません。
- 動きはキーフレームで書きます: `keyframes([[u0, [値…]], [u1, [値…]], …], u)` (区間ごとに滑らかに補間)。ループ動作は `u = (t % 周期) / 周期`。王のように単発攻撃の終端姿勢を保持する場合は、`u = Math.max(0, Math.min(1, t / 周期))` として終端で構えに戻します。ゲーム側での待機への切替とは区別します。
- 待機は呼吸 (`Math.sin(t * k)` で上下 0.8px 程度)、歩行は `walkFeet(t)`、攻撃は 構え → 溜め → 放つ → 戻す。
- **空いた手と剣の構え**: 盾を持たない腕に盾持ちの曲げた姿勢を流用せず、肩から自然に下ろした位置を基準にします。剣を下向きに構える場合は手を下げ、肘の曲がり・剣の傾き・長さを合わせて剣先が床に潜らないようにします。待機だけで完結させず、振り上げ・斬撃・戻りの手首と肘のつながりを4方向で確認します。王の `kingPose` と `SWING` は一例であり、座標を他の体格にそのまま適用しません。
- **攻撃の読みやすさ**: 放つ瞬間 (剣の振り下ろし・弓の離れ) の前後で姿勢を大きく変え、「溜め」の姿勢を少し長く保つと、通常のゲームサイズでも読めます。
- 歩行の周期は `1 / WALK_HZ` (共通) にします。ゲーム側は歩いた距離 × `walkSecondsPerTile` を `actionTime` に渡すので、周期が違うと足が滑ります。

## 4. 顔・髪・衣装の描き方 (実験Eで確かめたこと)

- **陰は同じ色の濃い色で**: `paint(ctx, 点列, { fill, w: LW.part, depth, light, speck })`。黒いハッチングは使わない。
- **線の太さの階層**: 外形 `LW.outline` (2.1) > 部品の境目 `LW.part` (1.6) > 細部 `LW.detail` (1.0) > 筋・しわ `LW.fine` (0.75)。
- **人間・エルフの顔は単純に**: 塗りつぶした縦長の楕円の目・短い眉・小さな口を基本とし、鼻・目のハイライトは省略します。これは人間系の表現例です。モンスターは指定された特徴を優先し、魔王・暗黒魔法使いのような影の顔と発光する目、骸骨の眼窩・鼻腔・歯を描き分けます。影の顔に不要な肌・口・鼻を足さず、背面には目や眼窩を描きません。
- **鋭い開口部の輪郭**: `paint` / `paintA` は輪郭を曲線でつなぐため、`round` を指定しなくても角が丸くなります。兜の眉・頬などはまず頂点の配置を整え、必要な部品だけ `step` (輪郭点の間隔) を小さくして角の丸まりを抑えます。[魔王](../characters/demon-king/character.js)の開口部は `step: 1` と小さな `amp` で調整しましたが、数値は形状ごとに決めます。厳密な直線が必要な面には公開の `fillPoly` も選択肢です。共通描画全体を変更せず、通常サイズで輪郭を確認します。類似の角穴の事例は[戦士の制作記録](archive/warrior/REPORT.md)を参照してください。
- **髪は「1つの塊 + ぎざぎざの縁 + 細い筋 + 明るい帯」**。房を1本ずつ輪郭付きで並べると、背面は松かさ・前髪は格子や歯に見える (剣士・弓使いの両方で同じ失敗をした)。前髪の先は眉より上で止める。
- **頭は正面系と背面系の2種類** を描き、`sx` で左右反転します。頭の形 (楕円) は全方向で同じにする (背面だけ大きく見えないように)。背面は情報が少なく「髪の丸」になりやすいので、はね・分け目・装備の一部などの目印を1つ足す。
- **手足は太く、手はミトン形**: `taperPts(a, b, 太さ0, 太さ1)` と `mittenHand(ctx, 手, 前腕の向き x, y, 大きさ, 色)`。
- **服は層で**: 下着 → 上着 → ベルト・留め具 → 肩掛け。ただし細部 (留め具・そばかす・木目) は通常のゲームサイズではほぼ見えない。ゲームサイズで効くのは「頭の形・髪と服の色・外形線の太さ・足元の量感」。

## 5. 武器・装備の取り付け

- 武器は **手の位置** (姿勢の値) から描きます。剣士: 剣の握り = 右手、盾 = 左腕（参考画像に合わせた新版）。弓使い: 弓の握り = 左手、弦と矢 = 右手、矢筒 = 背中。杖なら握り = 手、杖の向きを姿勢で決める。
- **左右は身体基準で維持する**: `b > 0` は左、`b < 0` は右です。方向変更にはリグの投影を使い、キャラクター全体の左右反転で持ち手を入れ替えないでください。王は右手に剣、左手は空きです。
- **王冠・帽子と頭の接続**: 頭と同じ座標系で描き、下縁が髪・頭の外形に自然に重なるようにします。輪郭を接するだけにすると、丸めた線や向きによって浮いて見えることがあります。縁・宝石などを含む装飾全体を一緒に調整し、正面・背面で髪との接続を確認します。頭を動かした場合は顎と襟の接続も確認してください。王では王冠を下へ3.5px、頭を下へ0.5px調整しましたが、これは倍率1のキャラクター固有値であり、共通の補正量ではありません。
- 武器の点は、床と同じ奥行き比で投影すると (`archer.js` の `UG`)、放った矢の飛ぶ向きとずれません。
- 背中の装備 (矢筒・マント) は、背面系で見えることを必ず確認する。
- **装備を追加・削除したとき**: 絵だけでなく接続部分・姿勢・描画順を見直します。[暗黒魔法使い](../characters/dark-mage/character.js)の魔法書は下端を右手の支持点とし、傾けても手から離れない位置に描き、空手の詠唱から本を掲げる動作へ変更しました。[骸骨弓兵](../characters/skeleton-archer/character.js)では肩掛けと留め具を削除した際に、露出する首・肩の骨をつなぎ、衣服用の描画順補正も見直しました。変更後は4方向と関連動作を確認し、`equipment`・`studio.description` を実際の装備に合わせ、カタログを再生成します。肩掛けを省くなどの選択は個別の制作指示であり、全キャラクターの原則にはしません。

## 6. 描画順の補正

部品は `{ id, d, draw }` の配列にして `renderRig` に渡すと、`d` の小さい順に描かれます。

- 基本: `d = bodyLayerKey(rf, a, b, z)` (部品の基準点)。胴を楕円柱、頭を球で近似し、「胴より奥 / 胴と頭の間 / 頭より手前」の3層 × ワールド奥行きで順番を決めます。胴・ケープ・頭は `LAYER.torso` / `LAYER.cape` / `LAYER.head`。
- **幅広いマントの遮蔽**: `bodyLayerKey` の胴体近似だけでは、胴より広いマントと腕の重なりを扱いきれません。背面で奥側の肩・肘・手・武器がマントの表に出ていないかをまとめて確認します。王では投影後の肩の奥行きから奥側の腕を判定し、関連部品の描画順キーを `LAYER.cape` 未満にして、腕を先に描いてからマントを重ねています。腕を消すのではなくマントで覆うため、外形から伸び出す部分は見えます。手前側の腕まで一律に隠さず、攻撃中も確認してください。補正はキャラクター側で行います。
- **肩掛けは袖を覆い、手・装備とは分ける**: 首元の短い肩掛けは、前後どちらの向きでも肩と袖の上にかぶさる衣服です。暗黒魔法使いでは袖の描画順を `Math.min(元の順位, LAYER.cape - 1)` に制限し、肩掛けを後から重ねました。手・杖・魔法書にはそれぞれの位置に応じた順位を残し、掲げた本や手まで一律に隠さないようにしています。長い背面マントの遮蔽とは対象が異なるため、衣服の形と重なる部位に合わせて補正し、4方向・攻撃中の代表姿勢で確認します。
- **胸の前の手**: 基準点が胴の楕円の内側に入ると前後が不定になるので、`a + 10` (胸と顎より前) として順位を決めた (弓使いの右手)。
- **長い部品は層の境界で分割**: 体の後ろの肘から胸の前の手へ伸びる前腕を1部品で描くと、顎の前に白い棒が立って見えた。肘と手が別の層にあるときだけ、前腕を肘側・手側に分けてそれぞれの順位で描く (`archer.js` の `fore('e')` / `fore('h')`)。杖・長い袖なども同じ。
- **読みやすさのために物理を曲げる**: 顎の下へ引いた弦は物理的には顔の前を通るが、顔が読めなくなるので弦の上半分を「頭の直前」の順位に制限した。誇張した箇所はコメントに書き残す。
- **向きごとの補正**: 大きな武器が顔に重なる向きでは、傾きを向きごとに選ぶ (弓の `bowCantSign`)。

## 7. Cached Frames のコマ割り

- 等間隔なら `frames: n`、重要な瞬間を必ず含めたいなら `keys: [0, …]` (0 から始まる昇順の位相)。弓使いは離れ 0.75 を含む20コマ (等間隔14コマだと矢が二重に見えるコマが出た)。
- **発射境界はコマ生成と選択の両方を確認する**: 発射コマを含めても、時刻から位相へ戻す計算や剰余の丸めで直前のコマが選ばれる場合があります。骸骨弓兵では発射位相 `0.75` で矢が残ることを確認し、キャラクター側で矢なしコマの開始を `0.75 - 1e-9` に置き、そのコマを描く姿勢の消去判定も同じ境界に合わせました。飛翔体の `releaseAt` は `0.75` のままです。これは今回の局所的な対処例であり、`1e-9` を一律の推奨値とはしません。共通キャッシュや既存弓使いを修正・全面検証したものでもありません。Live/Cachedそれぞれで発射直前・ちょうど・直後の手元の矢を確認し、飛翔体との重複確認は[Studioの確認範囲](STUDIO_GUIDE.md#依頼内容と確認範囲)と区別して報告します。
- コマ数の目安: 待機16・歩行10・攻撃14〜20 (× 4方向)。1コマ 151×147px (DPR 1・既定のカメラ) で RGBA 約89KB、160コマで約13.5MB。
- `frameBox` は絵が切れない大きさにします。現在の範囲検査は `tests/browser/check.html` で、全cache keyと中間位相を確認します。Studioで代表姿勢が表示できるだけでは、全位相での収まりを確認したことにはなりません。

## 8. 登録と確認

Studioへの登録は `node tools/sync-catalog.mjs` で行います。確認範囲・操作手順・完了報告は [STUDIO_GUIDE.md](STUDIO_GUIDE.md) の「依頼内容と確認範囲」「標準作業」を参照してください。

Studio内の確認は詳細画面の「全方向を見る」、再生・位相スライダー、拡大・通常ゲームサイズ、Live/Cachedを使います。ゲームでの接地・柱との遮蔽を検証する場合は、共通ダンジョンで実際に移動させてください。移植先で直接登録するAPIについては [API_REFERENCE.md](API_REFERENCE.md)、持ち出し手順については [EXPORT_GUIDE.md](EXPORT_GUIDE.md) を参照してください。
