# キャラクター制作・登録ガイド

## 単一の追加方法

`characters/<slug>/character.js` を作り、`node tools/sync-catalog.mjs` を実行します。直下のサブフォルダだけを探索します。ブラウザーは探索せず、生成済みの静的ES Moduleを読み込みます。`catalog.generated.js` は手編集しません。

```js
import { rigFrame, renderRig } from '../../src/authoring.js';
// 実際の制作では共通リグ・描画関数を使用し、全動作を実装してください。
function drawCharacter(ctx, x, y, direction, action, time, scale, opts) { /* 制作する描画 */ }
export const character = {
  id: 'your-character', label: '表示名', kind: 'humanoid',
  draw: drawCharacter,
  actions: {
    idle: { period: 3, frames: 20 },
    walk: { period: 1 / 1.4, frames: 16 },
    attack: { period: 1.4, keys: [0, .2, .38, .5, .55, .7, .85, .99], once: true },
  },
  frameBox: { x0: -90, x1: 90, y0: -140, y1: 30 },
};
export const studio = {
  name: '表示名', category: '職業・種類', description: '短い紹介。',
  preview: { direction: 'SE', phase: 0 }, // 任意。待機の代表位相
};
```

この例は登録形式を示す未完成テンプレートです。そのまま完成品として登録しないでください。周期・コマ割り・範囲・描画関数はInkstoneのCharacterDefinitionをそのまま参照し、カタログ用に複製しません。

- `id`: 英小文字から始まる英小文字・数字・ハイフン。一意であること。内蔵IDとの重複もエラーになります。
- `studio.name / category / description`: 必須。描画仕様以外の最小限のメタデータです。
- `studio.preview`: 任意。方向ありの既定はSE、位相0。位相は0以上1未満。
- 方向ありはNW / NE / SW / SEの4方向を実装します。既存キャッシュが4方向を一括生成するため、一部方向だけの定義は登録時に拒否します。
- 方向なしは `directional: false`。`preview.direction` を明示する場合はnull。UIは方向操作を表示しません。動作は `actions` に実装済みのものだけを記載します。
- 骸骨は4方向の待機・歩行・攻撃に対応します。右手の剣・左腕の盾を維持するため `direction` で向きを指定し、`unit.mirror` は使用しません。歩行は共通周期、攻撃は1.2秒の単発斬撃です。
- キャラクター固有の補助モジュールは同じフォルダ、複数キャラ共通の制作部品は `characters/shared/` に置き、相対パスの静的importを使います。依存情報は実際のimportグラフから収集します。
- 全キャラクターから共通の `game/index.html?character=<id>` へ移動できます。専用デモや `studio.demo` の指定は不要です。ダンジョンも同じカタログを参照します。歩行・攻撃は定義にある動作のみを使い、歩行なしの場合は待機姿勢で移動します。

## 人間型の標準頭身（灰燼の衛士を基準）

人間・人間型のアンデッドなどは、**約2.2頭身（目安2.1〜2.3頭身）**で制作します。骸骨の番兵も対象です。頭身は「頭頂から足裏までの高さ ÷ 頭頂から顎先までの頭の高さ」。羽飾り・角・帽子の突起・武器・盾・影は計測に含めません。兜は頭に沿う本体だけを頭の外形として扱います。

基準の `characters/warrior/character.js` は待機SE・位相0で、兜本体の頂点から顎先まで約42px（ローカル47px×0.9）、頭頂は接地原点より約92px上です。投影された足裏までを含めると約95〜98pxで、約2.2〜2.3頭身になります。羽飾り込みの全高や `frameBox` の高さを頭身に使わないでください。

- 同じ描画倍率で、頭の高さ約42〜45px、頭頂から接地原点まで約90〜94pxを初期目安にします（倍率1のローカル描画単位）。通常表示1.25倍でも比較します。
- 大きな頭・短い胴・短い脚を基本とし、頭だけ拡大したり完成画像を縦につぶしたりせず、キャラ側の関節位置・胴体寸法・首の接続を調整します。骨・鎧などの体質や装備の違いは残します。
- 4方向の待機を同倍率・同じ足元基準で衛士と並べ、頭身・身長・接続・装備の保持・描画範囲を確認します。背面の襟や後頭部だけで基準を測り直さず、SEの基準寸法を全方向で共有します。
- 特殊な体格は明示的な制作指示がある場合に個別設計します。この基準の追加だけを理由に、依頼対象以外の既存キャラを変更しません。

## 依頼内容と確認範囲

参考画像と文章で、名前・ID、種族や職業、外見で重視する部分、装備の左右、必要な方向・動作を指定します。「右手に剣、左手は空ける」「一度斬って待機姿勢へ戻る」のように、持ち手と動作の終わりも書くと意図が伝わります。

確認範囲と成果物も依頼ごとに指定できます。以下の標準作業を基本としつつ、見た目を相談しながら作る場合は「Studioで基本確認 → ユーザーの見た目確認 → 指摘箇所の微調整」という進め方を選べます。

- **Studioでの基本確認に絞る場合**: 構文・カタログ整合性、詳細画面の拡大・通常サイズ、4方向と対応動作の代表位相、再生、Live/Cachedの表示を確認します。腕・装備・マントなどの確認観点は [CHARACTER_GUIDE.md](CHARACTER_GUIDE.md) を参照します。全位相の描画範囲検査やダンジョンでの接地・遮蔽検査を省略した場合は、確認済みとは扱いません。
- **射撃を確認できる範囲**: 現在のStudio詳細・全方向一覧は `projectile: false` で描画しており、飛翔中の矢は表示しません。ここで確認できるのは、弓・弦・両手の接続、構えの方向、発射時に手元の矢が消えること、待機姿勢への復帰です。飛翔方向・発射位置の連続性・手元の矢と飛翔体の重複は、飛翔体を表示するゲーム側で別に確認します。Studioだけの依頼ではそのために専用デモを作らず、未確認として報告します。骸骨弓兵ではLive/Cachedの発射境界で手元の矢の消去を確認しましたが、飛翔表示とダンジョン内の詳細検証は未実施です。境界の実装上の注意は [CHARACTER_GUIDE.md のコマ割り](CHARACTER_GUIDE.md#7-cached-frames-のコマ割り)を参照してください。
- **成果物の要否**: 確認用の画像・動画・GIF、専用デモ、新規テスト、詳細レポート、ゲーム用エクスポートが必要かを指定します。今回不要という指定を、他の依頼にも一律の禁止として適用しません。
- **完了報告**: 変更内容と実施した確認・未確認事項を簡潔に伝えます。構文や登録形式の確認、AIによる目視確認、ユーザーによる見た目の了承は区別します。

## 標準作業

1. 依頼の確認範囲を踏まえ、`ARCHITECTURE.md`、`API_REFERENCE.md`、`CHARACTER_GUIDE.md`、関連する実装を読みます。
2. キャラクターを上記の配置・exportsで制作します。原則 `src/` を変更しません。
3. 共通リグ、接地補正、IK、描画層を使い、必要な方向・動作を実装します。
4. `node tools/sync-catalog.mjs`。重複・不足はファイル名付きで修正します。失敗時は既存カタログを置き換えません。
5. ギャラリーを再読込し、カード→詳細→拡大→通常サイズ→方向・動作→全方向一覧を確認します。
6. Live/Cachedを比較し、攻撃の重要な位相、装備の左右、頭身、接地、背面を目視します。
7. `tests/browser/check.html` で全登録キャラクターの `frameBox` を全cache keyと中間位相で確認します。既存戦士の部屋・遮蔽検査は `tests/browser/warrior.html` です。登録時の形式検査だけでは画素のはみ出しを検出しません。
8. エクスポートを含む依頼では、小さいキットを出力し、別フォルダから起動して確認します。
9. 定義・生成カタログを保存し、依頼された形式で検証結果を伝えます。仮キャラクターは残しません。

ギャラリーは待機の静止画を画面近くで一度だけ描きます。詳細は1体だけを再生します。Cached初回は既存エンジンにより全方向・全動作を同期生成し、一瞬停止します。現在のエンジンは動作単位の部分生成に対応していません。一覧展開は1つのCharacterViewのキャッシュを共有し、セルごとの複製は行いません。戻る・閉じる・Liveへの切替で不要なキャッシュを解放します。

通常サイズは倍率1.25×、DPR1。実際のゲームはカメラのズームにより見た目の大きさが変わるため、ゲーム組み込み時の最終確認はゲームのRendererでも行ってください。

## Studioに接続・操作できない場合

1. `npm start` または `start-studio.bat` で起動し、出力されたURLを使います。8081〜8090から利用可能なポートが選ばれるため、以前のURLや固定のポート番号を使い続けないでください。起動方法の詳細は [README.md](../README.md) を参照してください。
2. **サーバーへの接続不良**と**操作ツールのURL取得失敗**を分けて調べます。ブラウザーでページが開くか、ローカルHTTP要求に応答があるかを確認し、起動メッセージだけで接続成功とは判断しません。
3. 作業用サンドボックスでは、ローカル接続が `EACCES` で拒否されたり、そこで起動したサーバーにブラウザーから接続できなかったりする場合があります。環境の承認手続きに従って通常のローカル実行環境で起動し、再確認します。待受先は既存の `127.0.0.1` のままとし、接続確認のために外部公開やセキュリティ設定の変更は行いません。
4. ページは開くのにComputer Useが現在のURLを取得できない場合は、Studioの描画エラーと混同せず、ツールの停止指示に従います。利用可能なアプリ内ブラウザーなど、URLを正常に取得できる正式な操作経路で確認します。表示と操作が成功するまでは、目視確認済みと報告しません。

2026-10-21の王の制作では、通常のローカル実行環境でサーバーを起動し、アプリ内ブラウザーで開く方法で表示・動作を確認できました。一方、WindowsのComputer Useで通常ChromeのURLを取得できなかった**内部原因は未特定**です。これは接続・確認経路を確保した事例であり、Chrome側のURL取得問題そのものを修復したという記録ではありません。

## 制作AIへの指示テンプレート

> 添付資料を参考に、新しいキャラクター「［名前］」、ID「［id］」を制作してください。外見で重視する部分は［特徴］、右手の装備は［装備／空き］、左手の装備は［装備／空き］です。必要な方向・動作は［方向・動作・攻撃方法と終了姿勢］です。
>
> 確認範囲は［標準作業／Studioでの基本確認］、画像・動画・GIF、専用デモ、新規テスト、詳細レポート、エクスポートの要否は［指定］とします。［必要なら：細かな見た目は私が確認し、追加の調整を依頼します。］
>
> まずdocs/ARCHITECTURE.md、API_REFERENCE.md、CHARACTER_GUIDE.md、STUDIO_GUIDE.mdと実際の公開APIを確認してください。既存src/と完成済みキャラクターは変更しないでください。
>
> characters/［slug］/character.jsにInkstone CharacterDefinitionをcharacterとしてnamed exportし、studioメタデータを追加してください。共通リグ、接地補正、手描き描画、登録・キャッシュを再利用し、別の描画エンジンは作らないでください。方向ありなら4方向すべて、対応動作のみを実装してください。補助モジュールは静的な相対importにしてください。
>
> 人間型なら灰燼の衛士を基準に約2.2頭身（2.1〜2.3）とし、頭の高さ約42〜45px・接地原点から頭頂まで約90〜94px（倍率1）を目安にしてください。羽飾り・武器・影は頭身の計測から除き、同倍率で衛士と並べて確認してください。
>
> node tools/sync-catalog.mjsでカタログを更新し、ギャラリーUIを直接書き換えず追加してください。指定した確認範囲に従って既存Studioで確認し、必要な修正を行ってください。
>
> エクスポートが必要な場合はtools/export-game.mjsで持ち出し、独立したフォルダから起動確認してください。完了時は変更内容、実施した確認、未確認事項を簡潔に報告してください。仮の定義や検証専用キャラクターはカタログに残さないでください。
